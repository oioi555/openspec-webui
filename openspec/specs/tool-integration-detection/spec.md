# tool-integration-detection Specification

## Purpose
Detects which AI coding tools have OpenSpec integrations (commands and/or skills) configured for the active repository, and surfaces them read-only in Settings to guide users toward the correct invocation format.

## Requirements

### Requirement: Detect OpenSpec tool integrations in the repository
The system SHALL detect OpenSpec-generated tool-specific commands and skills present in the active repository, and SHALL report for each detected tool its name, whether it has Commands and/or Skills delivery, an example invocation for a representative workflow, and the detection source path. Detection SHALL look for OpenSpec-generated artifacts only (for example tool-specific `opsx-*` command files and `openspec-*` skill directories), SHALL NOT attempt to detect AI tool installation itself, SHALL treat detection results as hints rather than authoritative statements of tool support, and SHALL NOT treat an empty directory as detection. When no integrations are detected, the system SHALL NOT disable command copy functionality and SHALL NOT present the repository as unsupported.

#### Scenario: Detect a Claude Code command integration
- **WHEN** the active repository contains a `.claude/commands/opsx/<id>.md` command file generated by OpenSpec
- **THEN** the system reports Claude Code with Commands delivery
- **AND** the report includes an example invocation such as `/opsx:propose`
- **AND** the report includes the source path of the detected file

#### Scenario: Detect a skill integration
- **WHEN** the active repository contains an OpenSpec-generated skill directory such as `.claude/skills/openspec-propose/SKILL.md`
- **THEN** the system reports the corresponding tool with Skills delivery
- **AND** the report includes an example skill invocation

#### Scenario: Empty directories are not detected
- **WHEN** a tool directory exists but contains no OpenSpec-generated command files or skill files
- **THEN** the system does not report an integration for that tool

#### Scenario: Zero detection does not disable copy functionality
- **WHEN** the system detects no OpenSpec integrations in the active repository
- **THEN** command copy controls remain fully functional
- **AND** the candidate menu offers all official invocation forms

#### Scenario: Non-detection is not treated as unsupported
- **WHEN** a tool is not detected in the active repository
- **THEN** the system does not label that tool or the repository as unsupported

### Requirement: Expose detected integrations and forms via the API
The system SHALL expose the detected integrations and the resulting distinct invocation-form candidates through the command availability API for the active project, alongside the existing availability fields. The API response SHALL include a `delivery` value from CLI configuration, the detected integrations with their delivery and example invocation, and the deduplicated list of distinct invocation-form candidates used by the copy-time candidate menu. Existing availability fields SHALL remain present during the staged migration, with `availableExpandedCommands` marked as deprecated.

#### Scenario: API returns detected integrations
- **WHEN** the client requests command availability for an active project with detected integrations
- **THEN** the response includes each detected integration with tool name, delivery, and example invocation

#### Scenario: API returns distinct invocation-form candidates
- **WHEN** the client requests command availability for an active project
- **THEN** the response includes the deduplicated invocation-form candidates derived from detection
- **AND** identical candidate strings from multiple tools appear once

### Requirement: Tools section is read-only with guidance and detected integrations
The Settings sidebar SHALL present the section previously labeled `Workflow` under the short label `Tools`, with a more descriptive in-page heading permitted. The Tools section SHALL be read-only: it SHALL explain how OpenSpec installs per-tool commands and skills, SHALL link to the official supported-tools documentation at `https://github.com/Fission-AI/OpenSpec/blob/main/docs/supported-tools.md` via the shared documentation URL constant, SHALL explain that per-repository tool integrations are added or removed by re-running `openspec init`, SHALL list the integrations detected for the active repository (tool name, Commands/Skills delivery, example invocation, detection source), SHALL provide a refresh control that re-runs detection, and SHALL NOT contain any selection or format-fixing setting. The section SHALL describe detected content as "OpenSpec integrations configured for this repository" and SHALL NOT describe detected tools as "installed tools".

#### Scenario: Tools section shows explanation and documentation link
- **WHEN** the operator opens the Tools section in Settings
- **THEN** the section explains the integration mechanism
- **AND** links to the official supported-tools documentation using the shared URL constant

#### Scenario: Tools section shows init guidance
- **WHEN** the operator opens the Tools section in Settings
- **THEN** the section explains that re-running `openspec init` adds or removes per-repository tool integrations

#### Scenario: Tools section lists detected integrations
- **WHEN** the active repository has detected integrations
- **THEN** the section lists each detected integration with tool name, Commands/Skills delivery, example invocation, and detection source

#### Scenario: Tools section refresh re-runs detection
- **WHEN** the operator activates the refresh control in the Tools section
- **THEN** the system re-runs repository detection
- **AND** the detected integrations list updates to reflect the current repository state

#### Scenario: Tools section avoids installed-tools wording
- **WHEN** the Tools section renders its content
- **THEN** the copy refers to "OpenSpec integrations configured for this repository"
- **AND** does not describe detected tools as "installed tools"

#### Scenario: Tools section has no selection settings
- **WHEN** the operator views the Tools section
- **THEN** no command-format selection, global fixing, or per-command format-fixing control is rendered
